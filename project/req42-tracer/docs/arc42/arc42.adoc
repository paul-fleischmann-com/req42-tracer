== 4. Solution Strategy

=== 4.1 Overview

The tool follows a graph-based architecture:

1. Parse AsciiDoc blocks into structured model
2. Load Bausteinsicht architecture model
3. Build traceability graph (requirements → architecture → tests)
4. Analyze for gaps, coverage, ASPICE compliance
5. Generate reports (CLI, HTML)

[arch,id=strategy.graph,req=REQ-GRAPH-001,REQ-VALIDATE-001]
==== Traceability Graph

- Nodes: Requirement, Architecture Element, Test Spec, Test Code, Test Result
- Edges: satisfies, implements, verifies, derives
- Analysis: coverage, orphans, stale-detection

=== 5.5.1 Level 2 — C-Source Parser

[arch,id=comp.parser.c,parent=comp.parser,aspice=SWE.3,impl=src/internal/parser/cparser.go,req=SWR-C-PARSER-001]
==== C-Quellcode-Parser

Walks configured `c-sources` directories, extracts `@req`, `@arch`, `@aspice` and
inline `req:`/`arch:` annotations from `.c`/`.h` files, and returns a map of
`archElementID → file:func:line` impl-ref patches applied via `Builder.ApplyImplRefs()`.

[arch,id=comp.model.implref,parent=comp.model,aspice=SWE.3,impl=src/internal/model/impl.go,req=SWR-IMPL-REF-001]
==== ImplRef Model

`ParseImplRef(s)` parses all four `impl=` formats (Go package, file, file:func, file:func:line).
`ImplRef.ImplLink(baseURL)` generates a GitHub blob URL. Used by HTML report and validation rule.

=== 5.7 Level 2 — Plugin Subcomponents

[arch,id=comp.plugin,aspice=SWE.2,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-001,REQ-PLUGIN-002]
==== Plugin System

Provides stdin/stdout JSON protocol runner for external plugin binaries.
Supports 6 plugin categories: parser, enricher, validator, linker, reporter, notifier.

[arch,id=comp.plugin.runner,parent=comp.plugin,aspice=SWE.3,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-001]
==== Plugin Runner

Core execution engine: starts subprocess via `exec.CommandContext`, writes JSON request
to stdin, reads JSON response from stdout, applies 30s timeout. Returns typed result
or error on non-zero exit code.

[arch,id=comp.plugin.parsers,parent=comp.plugin,aspice=SWE.3,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-001]
==== Parser Runners

Typed runners for each parser plugin type:

- `RunTestResultParser` → `[]*model.TestResult`
- `RunRequirementParser` → `[]*model.Requirement`
- `RunArchParser` → `[]*model.ArchElement`
- `RunTestSpecParser` → `[]*model.TestSpec`
- `RunDesignParser` → `[]*model.DesignElement`

[arch,id=comp.plugin.enricher,parent=comp.plugin,aspice=SWE.3,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-002]
==== Enricher Runner

Calls enricher plugin with graph snapshot, receives `[]EnrichmentPatch`,
applies patches to `Requirements`, `ArchElements`, `TestSpecs` via `ApplyEnrichments`.

[arch,id=comp.plugin.validator,parent=comp.plugin,aspice=SWE.3,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-002]
==== Validator Runner

Calls validator plugin with graph snapshot, returns `[]ValidationIssue`
(rule, severity, element_id, message). Issues are collected alongside built-in validation results.

[arch,id=comp.plugin.linker,parent=comp.plugin,aspice=SWE.3,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-002]
==== Linker Runner

Calls linker plugin with graph snapshot, returns `[]*model.TraceLink`.
Links are merged into the builder before `BuildLinks()` executes.

[arch,id=comp.plugin.reporter,parent=comp.plugin,aspice=SWE.3,impl=internal/plugin/plugin.go,req=REQ-PLUGIN-002]
==== Reporter & Notifier Runner

- `RunReporter` — calls reporter plugin with graph + output_dir, returns generated file paths
- `RunNotifier` — calls notifier plugin with gaps payload as side-effect trigger

== 6. Runtime View

Describes dynamic behavior during execution.

[arch,id=runtime.trace,aspice=SWE.2,req=REQ-REPORT-001,REQ-VALIDATE-001]
==== Trace Command Sequence

[mermaid]
....
sequenceDiagram
    participant CLI as req42-tracer trace
    participant Cfg as model.LoadConfig
    participant Par as parser.ParseAllFromDir
    participant Bau as parser.BausteinsichtParser
    participant GC  as parser.ParseGoTestFiles
    participant TR  as testresult.LoadAll
    participant Grp as graph.NewBuilder
    participant Rpt as report.HTMLReporter

    CLI->>Cfg: LoadConfig(.req42.yaml)
    Cfg-->>CLI: *Config

    CLI->>Par: ParseAllFromDir(docs/requirements)
    Par-->>CLI: *TraceabilityGraph (reqs)

    CLI->>Par: ParseAllFromDir(docs/arc42)
    Par-->>CLI: *TraceabilityGraph (arch)

    CLI->>Bau: Parse(architecture.jsonc)
    Bau-->>CLI: *TraceabilityGraph (bausteinsicht)

    CLI->>GC: ParseGoTestFiles(src/)
    GC-->>CLI: *TraceabilityGraph (testcode)

    CLI->>TR: LoadAll(graph, config)
    TR-->>CLI: (test results merged)

    CLI->>Grp: MergeGraph(all graphs)
    Grp-->>CLI: *TraceabilityGraph (complete)

    CLI->>Rpt: GenerateReport()
    Rpt-->>CLI: report.html
....

Steps:

1. Load configuration (.req42.yaml)
2. Parse requirements (AsciiDoc)
3. Load architecture model (Bausteinsicht)
4. Parse Go test annotations
5. Load test results (JUnit XML / go-test JSON)
6. Build and merge traceability graph
7. Generate report

Configuration: `.req42.yaml` → `plugins.*` or `test-results[format=plugin]`.

== 12. Glossary

[glossary]
Requirement::
  A functional or non-functional system requirement, tagged with `[req,...]` in AsciiDoc.

Architecture Element::
  A system component or sub-component, tagged with `[arch,...]` in AsciiDoc.

Test Specification::
  A specification of test scenarios, tagged with `[test-spec,...]` in AsciiDoc.

Test Result::
  The outcome of a test execution, parsed from JUnit XML or go-test JSON.

Traceability::
  The bidirectional links between requirements, architecture, and tests.

ASPICE::
  Automotive SPICE (Software Process Improvement and Capability dEtermination), version PAM 4.0.

Graph::
  The internal dependency graph connecting all traced artifacts.
